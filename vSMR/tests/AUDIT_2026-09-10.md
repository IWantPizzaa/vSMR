# Audit disposition — 10 September 2026

The supplied audit describes `4af57c0`. On 11 September, commit `64ebfc1` was
reverted by `9d17833`, restoring the exact `38decf6` source tree before this
follow-up. The fixes below were then rebuilt from that baseline. The entries below distinguish concrete fixes
from recommendations that did not identify incorrect behavior.

| Finding | Resolution |
| --- | --- |
| Q1 — large functions | Profile normalization is split into named migrations; SDK tag capture is separate from tested formatting. Runtime Menu popup panels/actions, main/inset AVISO cache calculations, and SRW/AVISO aircraft/tag passes are separate helpers. All seven functions named in the audit were decomposed. The viewport functions still own their original drawing sequence and graphics lifetimes. See the function sizes below. |
| Q2 — namespace pollution | Removed `using namespace std` from application headers and qualified the affected declarations and uses. |
| Q3 — ignored validator results | Added `[[nodiscard]]` to updater URL, signature, hashing, package, path and inbound-message predicates. Builds treat compiler warnings as errors. |
| Q4 — manual resource cleanup | Both HTTP clients share a noncopyable WinHTTP handle owner. SHA-256 uses an owning digest object; both `goto cleanup` paths were removed. |
| Q5 — development checks | Shared build properties enforce `/W4 /WX`, `/permissive-`, CFG and `/Qspectre`. Debug is selectable in the solution. CI runs MSVC analysis, ASan JSON fuzzing, and an isolated ASan native regression suite. Use `/p:VsmrTestsAddressSanitizer=true` on `vSMR.Tests.vcxproj` for the native ASan build. This instruments the test harness and linked production modules; it does not establish full-plugin sanitizer coverage inside EuroScope. |
| Q6 — avoidable copies and modernization | SDK tag fields are captured into a value snapshot and formatted into reusable token storage. Formatting tests cover missing flight plans, correlation, clearance, Pro fallbacks, squawk errors, and the existing speed/altitude boundaries. Legacy/malformed profiles and every bundled profile are tested for repeat-run normalization. Existing randomness and logging fixes remain. Comprehensive host behavior still requires EuroScope testing. |
| S1 — old RapidJSON | Replaced the 0.11 subset with the complete upstream headers pinned to `24b5e7a8b27f42fa16b96fc70aade9106cf7102f`. Recorded source, commit, archive hash and license in `data/Licenses/DEPENDENCIES.md`. |
| S2 — unguarded parsing | Every production DOM parse now uses `shared/JsonDocument.hpp`. Both SAX and DOM passes use iterative parsing and validate UTF-8. Resource limits are checked before DOM allocation. A source check prevents new direct parse sites. |
| S3 — wildcard download hosts | Removed the `githubusercontent.com` suffix wildcard. Only explicitly named GitHub release/API hosts are accepted. Tests reject raw and arbitrary user-content subdomains. |
| S4 — revocation | The Authenticode bootstrap now requests certificate-chain revocation checking and fails closed when trust cannot be established. The configured signer pin continues to bypass bootstrap discovery. |
| S5 — TLS/port policy | Both clients require TLS 1.2 or newer and HTTPS port 443. TLS 1.3 is enabled when supported; failure to configure the TLS policy aborts the request. |
| S6 — NUL truncation | The common parser rejects embedded NUL bytes and parses the complete byte span. Signed manifests and unsigned release responses cannot silently accept a prefix. |
| S7 — binary hardening | Added compiler and linker CFG, compiler Spectre mitigations and conformance checking across runtime, loader, crash handler and tests. `/CETCOMPAT` is x64-only and does not apply to this x86 plug-in. |
| S8 — noted designs | The Hoppie query format is required by its API; existing HTTPS and log redaction remain. The per-user extraction script does not cross a privilege boundary. Neither observation establishes an additional bug. |
| P1 — tag model cost | Each scene buffer retains normal/detailed variants, line and element collections, and referenced input values. Unchanged definitions/inputs skip text evaluation; changed values update retained storage. Owning definition identities prevent stale cache hits after profile reloads. Hidden lines retain storage without occupying display rows or inflating visible-element diagnostics. Colors are still applied independently on every refresh. |
| P2 — font caches | Main, AVISO and secondary-radar tag caches persist between frames. Font, DPI, rendering mode, page scale and transform changes invalidate measurements. Entry and string-size limits bound memory growth. No persistent cache holds a frame's Graphics pointer. |
| P3 — SDK timing | Detailed per-call clocks run only in verbose diagnostics mode; normal refreshes still record inexpensive stage totals and call counts. |
| P4 — brush allocations | A bounded brush palette is reused throughout each tag/target pass, including trails and alert bands. |
| P5 — callback overhead | The target projection stage is templated on the concrete viewport projection and visibility callables. Its per-point loops no longer use type-erased callbacks. The common painter consumes projected coordinates from reusable storage, preserving polygon scaling, trail age/clipping, heading, and enabled layers. This permits inlining of the callable; it is not a guarantee that an SDK function call will inline. |
| P6 — logging allocation | The per-target icon trace accepts `const char*`; formatting happens after the verbose check. |
| P7 — hot maps | Refresh-local runway occupants, approaching aircraft, and countdowns now use reusable contiguous records, including retained string storage. Sorting by runway and insertion sequence preserves multimap duplicate ordering. Countdown collisions keep the last observed aircraft, matching the previous map. A deterministic 300-refresh comparison against the old container semantics covers duplicates, removal, runway changes, and countdown collisions. Existing token/hash-map fixes remain; persistent ordered configuration maps are unchanged. |
| P8 — hover copy and function size | Hover text still references the scene string. The oversized rendering functions were decomposed as described in Q1. No frame-rate improvement is claimed without a EuroScope workload. |

## Function decomposition

The seven original entry points now contain approximately 20–340 lines each.
Main AVISO retains its viewport setup and draw/request sequence (340 lines),
while cache operations are separate helpers. Inset AVISO has a 324-line viewport
function, a 195-line aircraft pass, and a 229-line tag pass. SRW separates the
242-line viewport from its 287-line aircraft/tag pass. Runtime Menu separates its
255-line rail/orchestrator from popup panels; click dispatch is 94 lines.
Profile migrations and tag formatting are tested without constructing a radar.

This follow-up preserves the original AVISO symbol-frame lifetime through tag
painting, and retains the original Runtime Menu rail body. Its renderer
extraction is narrower than the reverted commit.
